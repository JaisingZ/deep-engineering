# X 长文润色规则

这些规则来自一次已完成的长文改写，用来约束以后每一篇。润色只改表达和版式，技术内容、数字、引用和作者的判断保持原样。按金字塔原理检查结构时，可以把散落的同一论据收拢，并让判断提前到开头场景之后，不要重写成公文提纲。

## 保留什么

- 保留作者的判断、论据、步骤和术语。不新增事实，不补充原文没有的数字，不删掉技术内容。
- 可以改正错别字、病句和标点，理顺明显读不通的句子。
- 中文与英文、数字之间留一个空格。中文语境使用中文标点。
- 专有名词在同一篇里只用一种写法。

## 标题

X Articles 能稳定使用的是一级标题和二级标题，没有可用的三级标题。

- 章用 `#`，节用 `##`。
- `###` 以及更深的标题改成单独成行的粗体，不再使用标题语法。
- 章节顺序保持不变。

## 段落和列表

- 一段只写一个意思，控制在 2 到 4 句，读起来有停顿。
- 先给判断，再给依据。少用一逗到底的长句。
- 关键句可以单独加粗。不要把整段都加粗。
- 列表只表达并列项。X 长文不使用嵌套列表。原来的二级、三级列表压成一层：上一级写成引导句，原来的子项改成同一层的列表项，或改成紧接着的短段落。
- 同级列表项之间不插空行。

嵌套列表压平的例子：

```markdown
- 第一阶段
  - 人把问题复制出去
  - 结果要人自己带回仓库
```

写成：

```markdown
第一阶段，人还在流程外面搬运上下文。

- 人把问题复制出去
- 结果要人自己带回仓库
```

## 表格

正文表格改成列表，一行表格变成一个列表项。列名写进该项，数字原样保留。不要在润色稿里留 Markdown 表格。

```markdown
- 耗时：改造前 10，改造后 6
- 往返：改造前 4，改造后 2
```

表格只有一列说明时，列表项就只保留这一列的文字。

## 规范类附件与代码

嵌在正文里的规范、制度、检查单、说明性配置，改成普通正文，不要包在代码块里。整份附件用两行粗体包住，开始和结束都单独成行：

**【附：提交规范全文】**

这里是规范正文，使用二级标题无法表达的层级时改为粗体行，列表保持一层。

**【提交规范全文完】**

「提交规范」换成这份附件自己的名字。开始标记是 `【附：` + 名称 + `全文】`，结束标记是 `【` + 名称 + `全文完】`。

真正的代码、命令和需要保持等宽的片段仍用围栏代码块，并且保持简短。能删掉与论点无关的行就删到只剩说明问题的那几行；删行时不改剩余代码的含义。语言标记使用小写，无法判断时用 `text`。

## 篇幅

这三个限度同时生效。超出任何一个，就在章（`#`）的边界把文章拆开，不要从一节中间断开。

- **代码块。** X Articles 的接口会拒绝草稿，当围栏代码块里的内容超过大约 10000 个加权字符。CJK 统一表意文字、CJK 标点和全角字符每个计 2，其余字符每个计 1。只计算围栏内部，不算 ``` 那一行。同一篇草稿里的所有围栏相加。
- **全文。** 单篇正文控制在大约 25000 个字符（按 Unicode 字符计，不含文首 YAML）。这是阅读和草稿体量的经验上限。
- **图片。** 单篇最多大约 15 张。封面不计入正文图片。

拆成两篇时，标题后缀用「上」「下」。拆成三篇时用「上」「中」「下」。仍放不下就继续按章拆开，标题后缀改为「（1）」「（2）」这样的序号。文件名一律是 `article.x.part1.md`、`article.x.part2.md`，序号与阅读顺序一致。

从第二篇起，正文开头的第一句固定为：

```text
本文是系列第X篇，接上篇《…》。
```

`X` 是本篇序号，`《…》` 是上一篇的完整标题。不是最后一篇时，正文最后一行固定为：

```text
未完，见下篇。
```

最后一篇不要加这句。没有拆分的文章两句都不要加。

## 不要改成另一种文章

- 不把作者的技术判断改成口号。
- 不增加原文没有的产品、公司和人物。
- 不用代码块包裹已经改成正文的规范，也不把真正的代码改写成容易抄错的散文。

## 真人写作风格

润色同时应用 [skills/human-writing-style/SKILL.md](../../human-writing-style/SKILL.md)。阈值和禁用词在 [skills/human-writing-style/config/style-rules.md](../../human-writing-style/config/style-rules.md)。先按本文件处理版式，再按真人写作风格改表达，并用金字塔原理检查结构。

下面几处如果两边不一致，以真人写作风格为准：

- 段落可以只有一句。本文件写的「2 到 4 句」在超长或需要转场时让位：一段不超过 120 个汉字，长段后面接一句短段。
- 全篇加粗不超过 5 处，不用「加粗词加冒号」的列表。本文件允许关键句单独加粗，但不得超过这个上限。
- 不用「首先 / 其次 / 综上所述 / 总而言之 / 值得注意的是」这一类模板连接词，也不用「赋能 / 抓手 / 底层逻辑」这一类空词，不用 emoji。
- 结尾写一句短话，不写总结清单。不另设篇长目标。本文件里的代码块加权字符、正文字符数和图片张数是平台限制，继续有效。

不编造原文没有的经历、数字和人物。原文里已有的失败、插曲和零碎数字要留下来。原文没有自嘲时，可以补 1 到 2 句不引入新事实的轻自嘲；不要为了显得像人，编一个没有发生过的细节。
