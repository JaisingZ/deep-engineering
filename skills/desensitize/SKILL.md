# 脱敏

读取一篇文章的原文，找出敏感词，在将要进入草稿的材料里替换或打码。`article.md` 和原始图片保持不动。通过标准是：对脱敏后的材料再扫一遍，命中数为 0。

正式词表放在仓库之外的私有位置，由作者在运行时指定。`config/sensitive-words.txt` 只说明格式，里面的示例都是虚构的。仓库改为私有之前，不要把真实词条写进仓库。词表文件不存在，或手里只有这份模板时，停下来向作者要私有词表，不要用示例词假装已经脱敏。

## 词表格式

一行一条：`原词 => 替换词`。整行以 `#` 开头则是注释，空行忽略。一行里的 `=>` 只作为分隔符出现一次，两侧空白去掉。

- 替换词为空：这条只登记，标记为待人工复核，不得自行编造替换词。
- 行末的 `[img]`：该词出现在图片文字里时必须打码。写法是 `原词 => 替换词 [img]`，或 `原词 => [img]`。

含汉字的原词按子串匹配，这样句子中间的名称也会被找到。不含汉字的原词按标识符边界匹配：命中片段的前后必须是开头、结尾，或者不是字母和数字。因此连字符、下划线两侧算作边界。

匹配同时覆盖大小写变体，而不只覆盖词表里的那一种写法：

- 按词表原文做大小写敏感匹配。
- 再匹配全小写、全大写、仅首字母大写。`Foo` 会命中 `Foo`、`foo`、`FOO`。
- 这些变体出现在标识符里同样算命中，例如 `foo-xxx`、`FOO_xxx`、`xxx-foo`。
- 不把更长的字母单词拆开。`foo` 不命中 `food`，也不命中 `FooBar`。`FooBar` 只有自己出现在词表里时才命中。

多条规则都能命中同一处时，用更长的原词。替换词本身不得再包含词表里的原词。

## 扫描范围

对文章目录里的全部材料做扫描，模板目录除外。

1. **正文。** `article.md` 的段落、标题、引用、列表、链接文字和图片替代文本。
2. **代码块。** 围栏里面的内容同样替换，包括路径、主机名和账号。
3. **文件名。** 文章目录下的文件和子目录名称，包含图片文件名。
4. **图片里的文字。** 对每张图做文字识别（OCR），再用同一套规则看识别结果。
5. **截图里的人。** 个人头像，以及画面上的个人昵称，一律打码。头像不依赖文字识别是否认出文字。昵称包括词表中的昵称，也包括画面上明显的账号名、署名和对话气泡里的称呼。

`[img]` 用来强调「图片里必须打码」。没有这个标记的命中，只要出现在图片文字里，同样打码。待人工复核、替换词仍为空的条目，图片区域先打码，正文先记入遗留项，不猜测替换词。

## 怎么改

文本替换只发生在即将交给润色的正文上，不写回 `article.md`。

图片打码：

- 用文字识别框出命中文字，再把该矩形做强像素化。色块边长大约等于字高，盖住笔画。完成后肉眼和再次识别都不应再读出原文。
- 个人头像用同一强度盖住整个头像，不留可辨认的五官。
- **不覆盖原图。** 副本放在原图旁边，扩展名之前加上 `-redacted`。`images/flow.png` 写成 `images/flow-redacted.png`。
- 文件名本身命中时，原文件不改名。副本使用替换后的名字，再加 `-redacted`。虚构例子：`internal-svc-arch.png` 的副本是 `core-svc-arch-redacted.png`。替换词为空时，不要生成一个仍带敏感词的副本文件名；先作为遗留项停下。
- 润色稿里的图片路径改为相对路径，指向副本，例如 `![说明](../images/flow-redacted.png)`。路径相对于 `x/` 里的稿件。

一条规则处理完，再处理下一条。然后做复扫。

## 复扫

复扫对象是脱敏后的正文、打码副本的文件名，以及对打码副本重新做文字识别的结果。

不把 `article.md` 和未打码原图算进复扫。它们按设计仍保留脱敏前的内容。

复扫命中数必须为 0，才算脱敏完成。打码后仍能读出的区域，加大像素块再扫。替换词为空的条目、文字识别没把握的区域、看不清是否为人名的昵称，都算遗留项。有遗留项时复扫不能通过，也不要开始润色。

## 报告

写入 `articles/<目录>/x/desensitize-report.md`。每条命中单独一条，写明替换结果、文件和行号。文件名没有行号，行号位置写「文件名」。遗留项单独成节。报告含有原文，仓库公开时不要提交。

下面的形状使用词表模板里的虚构示例：

```markdown
# 脱敏报告

- 文章目录：
- 词表：私有词表的文件名，不抄全文
- 复扫范围：脱敏后的正文与打码副本

## 命中

- 文件 `article.md`，第 12 行：`示例公司` => `某公司`（正文）
- 文件 `article.md`，第 40 行：`internal-svc` => `core-svc`（代码块）
- 文件名 `images/internal-svc-arch.png`：`internal-svc` => `core-svc`，原文件保留，副本为 `images/core-svc-arch-redacted.png`
- 文件 `images/shot.png`（文字识别）：`secret-token` => `******`，已写入 `images/shot-redacted.png`

## 遗留

- 没有则写「无」。
- 有则写明文件、行号或画面位置、命中的原文、为何没有自动替换。

## 复扫

- 命中数：0
- 结论：通过。或：未通过，并列出仍然存在的命中。
```

命中数为 0 且遗留为「无」时，这一步才通过。
