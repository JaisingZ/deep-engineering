# 真人写作风格：可检查参数

`scripts/lint.py` 只读取本文件里 `lint` 围栏。围栏外面的说明给人看。写作目标有的比脚本更严，差在哪里写在对应的那一节。

这些数来自作者 78 篇掘金文章的统计，加上已经定下来的口径：口语克制，不用 emoji，每篇 1 到 2 处轻自嘲，标题以亲历型为主（问句和反差钩子可以用），段长不超过 120 个汉字，不规定篇长。

## 阈值

脚本按汉字计数（U+4E00–U+9FFF），不计标点、空格、数字和英文。

结尾的写作目标是 6 到 15 个字的一句。脚本放得更宽，只拦截不像一句短话的收尾：最后一段正文超过 40 个汉字，或者句末标点多于 1 个。

| 键 | 值 | 含义 |
| --- | --- | --- |
| bold_max | 5 | 全篇加粗超过这个数即违规 |
| emoji_max | 0 | 出现 emoji 即违规 |
| paragraph_han_max | 120 | 一段正文的汉字上限 |
| meme_max | 1 | 全篇热梗出现次数上限，同一个词重复也算 |
| ending_han_max | 40 | 最后一段正文的汉字上限 |
| ending_sentences_max | 1 | 最后一段正文里句末标点（。！？!?）的上限 |
| chain_min_distinct | 2 | 连接词链至少要出现几种不同标记 |
| stack_opener_min | 2 | 同一段里梯子的第一个词出现达到这个次数，即算叠加 |

```lint thresholds
bold_max: 5
emoji_max: 0
paragraph_han_max: 120
meme_max: 1
ending_han_max: 40
ending_sentences_max: 1
chain_min_distinct: 2
stack_opener_min: 2
```

## 禁用词

按子串匹配。同一处能被长短不同的词同时命中时，只记更长的那条。不扫围栏代码，不扫文首 YAML。

「首先」「其次」「再次」单独出现也记。它们同时参与下面的连接词链。「最后」不在这张表里。单独的「最后一步」是正常说法，只在连接词链里和锚点一起出现时才记。

不难发现

## 禁用的口语

允许的口语不在这里。这里是超过「克制」的说法，出现即违规。纯英文词不区分大小写，`yyds` 也能命中 `YYDS`。

```lint colloquial-banned
说白了
家人们
谁懂
绝绝子
yyds
破防
震惊
必看
吊打
居然
竟然
```

## 允许的口语

脚本不要求文章里一定出现这些词。用了不算违规。「好家伙」同时算热梗，次数受 `meme_max` 限制。

```lint colloquial-allowed
就是
比如
一下
好家伙
```

## 热梗

一篇最多 `meme_max` 次。同一个词出现两次算两次。「好家伙」可以用一次，第二次就超限。

```lint memes
好家伙
一把梭
炫几口
让子弹飞
```

## 连接词链

锚点里至少出现一个，并且「锚点 + 最后」里不同的标记达到 `chain_min_distinct` 种，记一条违规。只有「最后」、没有锚点，不记。

```lint chain-anchors
首先
其次
再次
```

```lint chain-markers
首先
其次
再次
最后
```

## 层层叠加

每一行是一组要按顺序出现的词。同一段正文里，这组词按顺序都出现，记一条。或者这一行的第一个词达到 `stack_opener_min` 次，也记一条。单独一次「不仅……而且」不记。

```lint stacking
不仅 而且 更
既 又 还
```

## emoji

下面这些字面量一定要命中。除此之外，脚本还认 Unicode 表情区间：表情符号、杂项符号、装饰符号、区域旗帜。组合符和变体选择符单独出现时不记。围栏代码里的表情不扫。

```lint emoji
✅
❌
⚠️
🚀
💡
```

## 加粗标签列表

脚本另外拦截这种列表行：列表标记后面紧跟 `**词**`，再跟全角或半角冒号。这是 AI 味列表，和加粗总数分开计。这条写死在 `scripts/lint.py` 里，没有单独的围栏。

违规形状：

- 列表标记，加粗词，冒号，说明

## 脚本不判断

这些仍要人看，或由润色规则另行约束：

- 轻自嘲是不是 1 到 2 处。一句就够，例如「又是被祖传代码教做人的一天。」不要整段卖惨
- 标题是不是亲历型（记一次… / 具体对象 + 具体动作或结果），或是不是问句、反差钩子
- 数字有没有场景、基线、环境或翻车过程
- 有没有至少一处一句话成段
- 篇长。不设篇长目标。代码块加权字符、正文字符数、图片张数仍由润色规则约束
- 有没有编造原文里不存在的经历、数字和人物
- 论点结构是否符合金字塔原理：顶层判断是否清楚，支撑点是否成组并指向该判断，证据是否落在对应要点之下，排序是否有理由（时间、结构或重要性）。检查方法见 SKILL.md，不要为了结构改成「首先 / 其次 / 综上所述」或总结清单
